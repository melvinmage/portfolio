1. La Couche Transport

La couche transport se positionne au-dessus de la couche réseau pour fournir aux applications un canal de communication de bout en bout, sans qu'elles aient à se soucier du fonctionnement exact de l'infrastructure matérielle ou du routage.

TCP et UDP : Les deux géants

La couche transport découpe les données des applications. Ces blocs d'informations se nomment Segments (pour TCP) ou Datagrammes (pour UDP).

  • TCP (Transmission Control Protocol) : Protocole orienté connexion qui garantit l'intégrité des données. Il utilise le Three-Way Handshake (SYN, SYN-ACK, ACK) pour établir une connexion fiable. Il s'assure via des acquittements que rien n'est perdu (ex: Web, FTP).
  • UDP (User Datagram Protocol) : Protocole minimaliste, sans connexion et en mode datagramme. Très rapide, mais ne garantit rien. Idéal pour la Voix sur IP (VoIP) ou le streaming vidéo. Si un datagramme UDP est corrompu ou perdu, il est jeté silencieusement par le récepteur (l'application ne reçoit rien du tout, pas d'avertissement).

En-tête UDP

L'en-tête UDP est très court (8 octets). Il ne contient que 4 champs : le Port Source, le Port Destination, la Longueur et la Somme de contrôle (Checksum). Il n'y a pas de numéro de séquence contrairement à TCP.

Le principe des Ports (16 bits)

Pour gérer plusieurs applications sur une même machine, on ajoute un numéro de port codé sur 16 bits à l'adresse IP. Au niveau d'un serveur, le numéro de port permet à plusieurs clients de se connecter au même service simultanément.

Les ports sont divisés en catégories :

  • Well-known (Bien connus) : De 1 à 1023 (Réservés aux services standards comme HTTP:80, HTTPS:443, SSH:22).
  • Enregistrés : De 1024 à 49151.
  • Dynamiques / Privés : De 49152 à 65535 (souvent utilisés par les clients pour initier la connexion).

2. Le Service HTTP

HTTP signifie HyperText Transfer Protocol. C'est le protocole à la base du Web, fonctionnant selon un modèle Client-Serveur. Il s'appuie sur le protocole de transport TCP.

Fonctionnement & Ports

Le serveur écoute généralement de manière statique sur le port 80 (HTTP) ou le port 443 (HTTPS - version chiffrée). Le client (le navigateur web), quant à lui, réserve son port de communication de manière dynamique (port éphémère) lors de la requête.

Si le serveur reçoit une requête HTTP bien formulée, il renvoie le contenu demandé accompagné d'un 'Content-Type' (ex: text/html) pour indiquer au navigateur comment l'afficher.

Les Méthodes et Codes de Statut

Le client communique ses intentions via des "méthodes" :

  • GET : Pour demander le chargement d'une page ou d'une ressource.
  • POST : Pour envoyer les données d'un formulaire au serveur.
  • PUT : Pour modifier une ressource.
  • DELETE : Spécifiquement utilisée pour supprimer une ressource.

Le serveur répond avec des codes à 3 chiffres :

  • 200 OK : Indique un succès absolu.
  • 404 Not Found : Indique que la page ou la ressource n'existe pas.

3. Le Service DHCP

Le rôle principal du Dynamic Host Configuration Protocol (DHCP) est l'allocation dynamique d'adresses IP et de configurations (Masque, Passerelle, DNS) pour éviter une configuration manuelle laborieuse. Il utilise le protocole de transport UDP sur les ports 67 (serveur) et 68 (client).

Le processus D.O.R.A

C'est l'échange en 4 étapes lors de la connexion d'un nouveau client :

  1. Discover : Le client cherche un serveur. Comme il ne connaît pas l'IP du serveur, il envoie sa requête en diffusion (Broadcast) sur l'adresse 255.255.255.255. Et comme il n'a pas encore d'IP, son IP source est 0.0.0.0.
  2. Offer : Le serveur répond avec une proposition (bail) contenant une adresse IP valide.
  3. Request : Le client valide l'offre. S'il y a 2 serveurs DHCP sur le réseau, il n'accepte qu'une seule configuration. Par ce message, il avertit qu'il accepte une offre spécifique et décline les autres.
  4. Acknowledge (ACK) : Le serveur confirme définitivement le bail.

Gestion du Bail IP

L'adresse est "louée". À la moitié (T/2) de la durée de vie du bail, le client va naturellement tenter de renouveler son bail auprès du serveur.

Si la machine veut rendre son IP avant la fin (résiliation explicite), elle envoie un message DHCPRELEASE. Si le client détecte que l'IP proposée est déjà utilisée sur le réseau (conflit), il envoie un message DHCPDECLINE.

4. Le Service SSH

SSH (Secure Shell) est un protocole qui remplace les anciens outils non sécurisés comme telnet et rsh. Il permet l'administration de machines à distance de façon sécurisée et écoute par défaut sur le port 22.

La Cryptographie Hybride

SSH combine deux types de cryptographie pour allier sécurité et performance :

  • Asymétrique (Clé publique/privée) : Elle est très sécurisée mais nécessite des calculs trop complexes et lents pour envoyer de gros fichiers. Elle est donc utilisée uniquement au début pour générer et s'échanger une clé secrète partagée sans jamais l'envoyer en clair sur le réseau (grâce à l'algorithme de Diffie-Hellman). Règle d'or : Un message chiffré avec la clé publique de Pam ne peut être déchiffré que par la clé privée de Pam.
  • Symétrique : Une fois la clé secrète partagée via l'étape 1, elle est utilisée pour chiffrer tout le reste du transfert de données en masse, car c'est beaucoup plus rapide.

Outils et Fonctionnalités Avancées

Sous Windows, le logiciel client SSH le plus populaire est PuTTY. SSH vient aussi avec des outils intégrés comme scp (Secure Copy Protocol), qui permet de transférer des fichiers de manière sécurisée de machine à machine.

Enfin, SSH permet le Tunneling : c'est une technique géniale pour faire passer (rediriger) un autre protocole (comme HTTP ou FTP) de manière chiffrée à l'intérieur de la session SSH.

5. Le Service DNS

Le Domain Name System (DNS) sert d'annuaire à Internet : il associe un nom "humain" (logique) à une adresse IP compréhensible par les machines. Il écoute généralement sur le port 53 (UDP et TCP).

Historique et Hiérarchie

Avant l'invention du DNS, ce processus fastidieux se faisait grâce à un fichier local (ex: /etc/hosts en UNIX) mis à jour manuellement. Aujourd'hui, le DNS est hiérarchisé :

  • La Racine (.) : Il existe exactement 13 serveurs "Racine" dans le monde.
  • Les TLD (Top Level Domain) : C'est l'extension de premier niveau (ex: .com, .fr, .net).
  • Pour créer un sous-domaine (ex: etu.uca.fr), il faut obligatoirement l'autorisation de l'organisme gérant le domaine père (uca.fr).
  • Une Zone DNS est une partie de l'espace de noms DNS gérée par un serveur spécifique, contenant les enregistrements (A, MX...).

Méthodes de Recherche et Avantages

Il existe deux modes de résolution lorsqu'un serveur DNS local ne connaît pas la réponse :

  • Mode Itératif : Le serveur local fait tout le travail et interroge lui-même successivement la racine, puis le TLD, puis le serveur d'autorité.
  • Mode Récursif : Chaque serveur visité prend l'initiative d'interroger le serveur suivant à la place du demandeur.

Un avantage majeur du DNS est la répartition de charge (Load Balancing). En effet, un même nom de domaine peut renvoyer plusieurs adresses IP différentes, permettant de distribuer le trafic sur plusieurs serveurs web.
